# T-FLEX Experiment Plan

**Status:** Phase 1 draft. The matrix is `configs/experiments.yaml`. No experiment has been run; this document defines what will be run and how it will be measured.

---

## 1. Research questions → experiments

| RQ | Question | Primary evidence |
|---|---|---|
| RQ1 | How does 3D stacking change thermal behaviour vs 2.5D under identical workloads? | E1 vs E2 per workload; E0 sensitivity to bond / TIM / heatsink parameters |
| RQ2 | How much throughput is lost to thermal throttling? | E3 vs E2: link bandwidth, workload completion time, time above T1 |
| RQ3 | Can thermal-aware routing cut peak temperature at acceptable throughput? | E4 (threshold, cost, γ sweep) vs E2 |
| RQ4 | How much bandwidth is lost after lane failures? | E5 bandwidth before / during / after repair vs failed lanes |
| RQ5 | How much redundancy is needed for k failures? | E5 `spare_lanes` sweep × failure counts; `MAX_SHIFT` variants (area from synthesis) |
| RQ6 | Tradeoff between thermal management, reliability and performance | E6 vs E2–E5; Pareto plots (throughput vs peak T vs faults) |
| RQ7 | How does workload type influence thermal behaviour? | every experiment × {matmul, attention, weight_load} |

Each configuration runs 3 workloads × 5 seeds for 1000 epochs (1 s of scaled physical time) after 50 warm-up epochs. Reported values are the mean over seeds with a 95 % confidence interval (Student t, n = 5). Policy comparisons use common random numbers (same workload seed, same fault random stream) and report paired differences.

## 3. Metric definitions

Performance
- **Link bandwidth / throughput:** payload bytes delivered per second per direction (headers, replays, pads and training excluded); also raw link utilization = valid beats / cycles.
- **Workload completion time:** time until all phases complete; primary throughput metric for RQ2 because it includes compute stalls.
- **Packet latency:** completion time − `inject_ts` per transaction (mean, p50, p99, max).
- **Retry latency:** time from a NAK to delivery of the NAKed flit.

Thermal
- **Peak / average temperature:** max over time of max over tiles of a die; time-average of the die mean.
- **Thermal gradient:** max − min tile temperature within a die (in-plane) and across the stack (vertical), max over time.
- **Time above threshold:** fraction of time any tile ≥ T1 (also T2, T3).
- **Thermal recovery time:** from a throttle action until the sensor falls below `T1 − H`.

Reliability
- **Recoverable lane failures:** largest k with the link returning to ACTIVE at full width (and at any width).
- **Repair latency:** protocol.md §7 definition, broken into detection / drain / training / deskew.
- **Packet errors / loss:** CRC errors, retries, retry rate (replayed / new flits), undetected corruptions (`sig_errors`), transactions never completed.

Efficiency
- **Energy/bit:** (PHY + adapter energy) / payload bits delivered; system variant includes memories and compute.
- **Energy/packet**, **performance/W** (payload throughput per watt).

Hardware (synthesis, pre-layout)
- cell area (µm², Nangate45; sky130 as a second PDK), cell and register counts, combinational depth / ABC delay estimate, "estimated fmax" from that delay; FPGA LUT/FF counts via `synth_xilinx`. Reported for adapter, PHY, lane mapper (`MAX_SHIFT` variants), async FIFO, LTSM. Labeled pre-layout estimates.

## 5. Expected outcomes stated in advance (to be confirmed or refuted)

Recording expectations before running protects against post-hoc storytelling:

1. 3D runs hotter than 2.5D for the same workload, with the memory die close to the AI die's temperature, and the gap shrinks as the hybrid-bond conductivity rises.
2. Link-only throttling reduces temperature mainly through the compute stall it causes; the throughput cost will be visible in completion time more than in link bandwidth.
3. Thermal-aware routing reduces the peak temperature near link A's PHY by a small amount (≈ 1 °C or less) at a latency / energy-per-bit cost from using link B; the γ sweep shows where that tradeoff saturates.
4. With 4 spares, up to 4 permanent failures cost only retrain time; failure 5 drops the link to 24 lanes (≈ 25 % bandwidth loss plus pads) if `MAX_SHIFT` allows it, otherwise the link goes down.
5. Retry-buffer stalls appear when `RETRY_DEPTH` is below the ACK round trip (X1).
